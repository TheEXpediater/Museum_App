PART 1. BACKEND OPENCLIP WARMUP

Implement an admin-protected warmup flow for the live FastAPI process.

Recommended endpoints:

POST /api/v1/ai/warmup
GET /api/v1/ai/warmup/status

POST /api/v1/ai/warmup must:

1. Require administrator authentication.
2. Start model loading in the live FastAPI server process.
3. Avoid blocking the Android request during a long first download.
4. Return HTTP 202 when loading starts.
5. Return the current state when loading is already in progress.
6. Return loaded immediately when the model is already loaded.
7. Prevent duplicate simultaneous model loads.
8. Keep the state in a thread-safe singleton service.
9. Never persist a test image.
10. Never create a fake artifact.
11. Never add a test vector to Qdrant.

Use a background task or executor and a lock.

Warmup states:

idle
loading
loaded
failed

Warmup status response:

{
  "state": "loaded",
  "message": "OpenCLIP is ready.",
  "model_name": "ViT-B-32",
  "pretrained": "laion2b_s34b_b79k",
  "device": "cpu",
  "embedding_dimension": 512,
  "started_at": "...",
  "completed_at": "...",
  "duration_seconds": 0.0,
  "error": null
}

To verify full inference, generate a small in-memory RGB image and pass its bytes through the existing OpenCLIPEmbeddingService. Do not write the image to disk. Reuse the current model manager and embedding service. Do not add a second OpenCLIP implementation.

When warmup fails:

1. Store a safe message.
2. Log the technical exception on the backend.
3. Do not expose cache paths, secrets, or stack traces through the API.
4. Allow Retry.

Optional setting:

AI_WARMUP_ON_STARTUP=false

When true, start the same background warmup during FastAPI startup after the application is ready. Keep false as the default to avoid slow startup during development.
